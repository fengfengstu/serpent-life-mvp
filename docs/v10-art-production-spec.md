# 《此生为蛇》V10 美术生产规格 v0.1

日期：2026-06-21  
状态：用于资产提案与生成前的生产约束  
当前锁定方向：主角蛇采用“版本 2：皇家圣鳞”的审美方向

## 1. 先区分三类图

V10 不再把“好看的概念图”直接当游戏资产。所有美术输出分三层：

| 类型 | 用途 | 是否直接进游戏 | 要求 |
| --- | --- | --- | --- |
| 方向稿 | 选择审美、材质、气质 | 否 | 可以是完整构图，但不能当 sprite |
| 生产规格图 | 确定结构、角度、模块、比例 | 否，作为生成/切图蓝图 | 必须拆件、正交、无场景、无复杂光影 |
| 游戏资产 | 实际进游戏 | 是 | 透明 PNG/WebP、统一尺寸、统一锚点、可旋转、可动画 |

当前已经生成的版本 2 只属于“方向稿”。下一步必须做“生产规格图”，再从规格图拆出正式游戏资产。

## 2. 主角蛇不采用传统三视图优先

普通角色常用正面、侧面、背面三视图，但《此生为蛇》的主角是 top-down / 斜俯视蛇形移动游戏，传统三视图不是最关键产物。

主角蛇真正需要的是：

1. 俯视/轻俯视 head sprite，朝上为默认方向。用户标注图中的红色箭头方向就是蛇头前进方向；红框内才是头部模块。嘴/鼻孔下方不能直接露出或顶上身体段，否则会读成“蛇头咬住身体”。
2. 模块化 body segment，前后接口对齐，旋转后不露缝。
3. memory segment，作为身体中的发光节点。
4. tail sprite，朝上为默认方向，代码旋转。
5. hurt / cleanse / death 的覆盖层或替换帧。
6. 统一碰撞圆和视觉锚点。

三视图可以作为理解形体的辅助，但不应先做成 3D/影视角色设定。游戏资产优先服务操作、碰撞、旋转和可读性。

## 4. 主角蛇规格图要求

下一轮生成“皇家圣鳞主角蛇生产规格图”，而不是漂亮展示图。规格图必须包含：

1. 单独头部，朝上，正交或轻俯视；必须符合用户标注图：红色箭头方向为前进方向，红框内为头部模块，嘴/鼻孔下面不能接身体段。脖颈/身体连接点只能藏在头部后方或下缘遮挡区，不能顶到嘴下面。
2. 单独身体段，朝上，前后接口清晰。
3. 单独记忆身体段，朝上，发光点位清晰。
4. 单独尾巴，朝上。
5. 小比例游戏内预览：头 + 8 节身体 + 尾巴，验证连接感。
6. 碰撞圆/锚点示意可以用淡线标注，但正式游戏资产不能带标注。

禁止：

- 整条蛇只画成一个不可拆的 S 形大图。
- 复杂背景、投影、场景光。
- 半透明主体。
- 大量噪点细节。
- 头和身体比例不适合拼接。
- 左右镜像或上下翻转导致头部朝向错误。

## 5. 正式游戏资产规格

### 5.1 画布

- 头部源图：512 x 512。
- 身体/尾巴源图：256 x 256。
- 图标源图：256 x 256。
- 技能粒子源图：64 x 64 或 128 x 128。
- UI 九宫格源图：128 x 128、256 x 256 或 512 x 512。

### 5.2 背景与透明

正式资产必须是透明背景 PNG/WebP。  
如果使用图像生成工具无法直接稳定输出透明底，则先生成纯色 chroma-key 背景，再本地抠透明。

所有资产必须：

- 无环境背景。
- 无接触阴影。
- 无地面投影。
- 无水印。
- 无文字。
- 主体与画布边缘至少保留 12% 安全边距。

### 5.3 锚点

| 资产 | 锚点 |
| --- | --- |
| 蛇头 | 几何中心略偏后，保证沿箭头方向旋转时头部不漂；第一节身体必须压在头后方，不得压到嘴/鼻孔下方 |
| 身体段 | 几何中心 |
| 记忆段 | 几何中心 |
| 尾巴 | 几何中心略偏前 |
| 弹道 | 几何中心或发射点，按类型标注 |
| UI 图标 | 几何中心 |

蛇头必须额外记录两个语义点：

- `face_forward_point`：鼻子/嘴所在的前端点，永远朝移动方向。
- `neck_socket_point`：身体连接点，永远位于 `face_forward_point` 的反方向。

验收标准很简单：如果把第一节身体接上去后，视觉上像“鼻子/嘴下面长出身体”或“蛇头咬住身体”，这个头部资产直接判定不合格。

用户已确认的正误对照：

- 错误头部：鼻子/嘴在下方，身体会接到嘴下面。
- 正确头部：鼻子/嘴在上方，底部是脖颈/身体接口。

后续所有主角蛇资产以“正确头部”为准：脸朝上，身体接下方，连接处不能出现嘴、鼻孔、牙或下颌读感。

### 5.4 碰撞范围

视觉图形和碰撞不完全一致。建议：

- 蛇头碰撞圆：视觉头部宽度的 55%-65%。
- 身体段碰撞圆：视觉身体宽度的 50%-60%，第一版身体可不参与受击。
- 普通敌人碰撞圆：视觉宽度的 60%-70%。
- 经验/记忆拾取：吸附半径大于视觉半径 2-3 倍。

## 6. 蛇身拼接方案

蛇身不靠一张完整弯曲大图实现，而靠模块化 sprite 沿移动路径拼接。

### 6.1 路径采样

游戏每帧记录蛇头路径点，身体段按固定间距从路径历史中采样：

1. 蛇头是路径第 0 点。
2. 第 1 节身体从路径后方固定距离采样。
3. 后续身体段继续按同样距离采样。
4. 记忆段只是身体段的替换皮肤，不改变碰撞和间距。
5. 尾巴采样在最后一个身体点之后。

### 6.2 旋转规则

所有 sprite 的默认方向统一为：

- 蛇头：用户标注图的箭头方向为前进方向；红框内为头部；身体接口藏在头后方/下缘遮挡区；严禁出现“嘴巴朝身体”的读感。
- 身体：纵轴朝上/下，前后接口一致。
- 尾巴：尾尖朝下，身体接口在上。

运行时旋转规则：

- 身体段按当前采样点前后两个路径点的切线旋转。
- 蛇头朝“前进方向”旋转，也就是远离身体的一侧，而不是朝向尾巴。
- 尾巴朝路径末端方向旋转，尾尖远离身体。
- 禁止使用左右镜像修方向，所有方向错误都通过旋转角度修正。

### 6.3 重叠与间距

身体段必须轻微重叠，不能刚好首尾相接。建议：

- 身体段显示长度：`44-56 px`。
- 采样间距：显示长度的 `62%-75%`。
- 大转弯时允许更密集，避免露缝。
- 头和第一节身体需要独立锚点偏移，保证脖颈压住第一节身体。

### 6.4 当前验证结论

已用 `royal-serpent-modular-sheet-corrected.png` 拆出头、身体、记忆段、尾巴，并生成 S 形程序拼接预览：

- `royal-serpent-s-curve-assembly-preview-v2.png`

验证结果：

- 可行：版本 3 的身体段可以通过路径采样拼出弯曲蛇身。
- 可行：记忆段作为替换身体段能保持可读性。
- 需要保留：头部必须用“朝前”角度，而不是身体切线朝尾巴方向。
- 需要优化：当前规格图里的头部视觉前端容易误读，正式资产导出时必须重做或修正头部，让嘴、鼻孔和眼神远离身体方向，而不是从规格图硬裁。

## 7. 技能资产不是大贴图

技能效果不生成“一个完整大火环”“一个完整大冰环”贴上去。正式技能由代码组合以下小资产：

| 技能类型 | 资产组件 |
| --- | --- |
| 火系 | 火星、短弧、余烬、爆点、小型扫尾纹 |
| 冰系 | 雪花核心、冰晶碎片、细线裂纹、短拖尾 |
| 盾系 | 鳞片光斑、六边护纹、小型反光片 |
| 牙刃 | 牙形弹头、短尾迹、命中碎屑 |
| 链电 | 小电弧段、节点闪点、跳跃连线纹 |
| 磁吸 | 小记忆光点、吸附线、旋入粒子 |

每个技能第一版只需要 3-6 个小组件，由引擎负责旋转、缩放、叠加、淡入淡出和轨迹。

## 8. UI 资产规格

UI 也不能只是一张整屏效果图。需要拆为：

1. HUD 背板九宫格。
2. 身体生命条刻度。
3. 技能珠提示面板。
4. 技能卡普通/稀有/高消耗/不可购买状态。
5. 暂停按钮。
6. 关卡选择按钮。
7. Boss 血条。
8. 技能图标。

UI 约束：

- 不使用过度透明。
- 文字区域留足空间，避免移动端溢出。
- 图标必须一眼识别，火就是火苗，冰就是雪花/冰晶，盾就是盾牌。
- 装饰边框不能压过可读性。

## 9. 后续提案顺序

用户已经偏好“版本 2：皇家圣鳞”。后续按这个顺序继续，每一轮只做一类资产，每类三版：

1. 主角蛇生产规格图：头、身体、记忆段、尾巴、拼接预览。
2. 主角蛇正式透明资产：根据选中的规格图拆件。
3. 技能图标：火、冰、盾、牙刃、磁吸、速度、链电、护身、贯穿。
4. 技能特效组件：小粒子、小弧线、小弹道、小光点，不做大贴图。
5. 敌人普通怪与精英怪。
6. Boss 设计。
7. UI/HUD。
8. 关卡地面与章节视觉。
